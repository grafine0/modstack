# Agent Session Journal — 2026-11-09

## Objective

Remediate the critical and high-priority security and reliability findings identified in the static security audit of ModStack (`SEC-001` through `SEC-007` and `REL-001` through `REL-004`), verify with automated unit tests, and push the changes to a dedicated Git branch (`security/audit-remediation`).

## Investigation

1. **Archive Extraction (`SEC-001`)**: `PackageInstaller.ExtractPackageAsync` and `FrameworkPackageInstaller.ExtractPackageAsync` combined archive-supplied entry paths with the target extraction root without canonical containment checks, staging isolation, duplicate destination detection, or Zip Bomb quotas.
2. **Download Transport & Integrity (`SEC-002`, `SEC-003`)**: `PackageInstaller.GenerateNginxDownloadUrl` used insecure `http://`, and `DownloadPackageAsync` neither enforced HTTPS nor rejected size mismatches or verified SHA-256 digests.
3. **Certificate Generation & CLI Exposure (`SEC-004`, `SEC-005`)**: `SSLCertificateService` interpolated domain names and passwords into PowerShell `-Command` strings and passed `-passin pass:{password}` via OpenSSL command-line arguments. Furthermore, `ExtractPfxToPemWithDotNetAsync` loaded PFX files without `X509KeyStorageFlags.Exportable` and attempted direct `ExportRSAPrivateKey()` on Windows CNG keys that only allow encrypted PKCS#8 export.
4. **Privilege Level (`SEC-006`)**: `ModStack.GUI/app.manifest` required full administrator elevation (`requireAdministrator`) by default.
5. **Hostname Validation & Apache Activation (`SEC-007`, `REL-001`)**: `VirtualHostService` checked only for spaces and a dot in domains, did not validate aliases, and launched `TestAndRestartApacheAsync` in an unawaited `Task.Run`.
6. **Service Registration & Metadata (`REL-002`, `REL-003`, `REL-004`)**: `PackageInstaller` silently swallowed service registration and startup failures; `UpdateService` returned fake `mock.example.com` updates; `DefaultPackages.json` mapped Redis `7.2.3` to a `3.0.504` `.msi` artifact.
7. **Phase 2 Follow-Up Findings**:
   - `PHPExtensionManager` combined `extDir` and `dllName` without canonical path containment and allowed weak `MD5`/`SHA1` extension hashes.
   - `PackageInstaller.InstallPackageAsync` left partial installation directories behind when post-extraction steps failed.
   - `ModStack.GUI.csproj` referenced unused `System.Security.Cryptography.Xml` (`10.0.9`) and `Microsoft.Windows.Compatibility`, triggering 8 `NU1903` high-severity vulnerability warnings.
   - `DependenciesTypeHandler` was missing from `ModStack.Data` and `ConfigurationTypeHandler` widened 32-bit JSON integers to `double`.

## Decisions

- Centralized security validation in `ModStack.Common.Security.SecurityValidator` and safe archive extraction in `ModStack.Common.Security.SafeArchiveExtractor` so all service, core, GUI, and test projects share one authoritative implementation.
- Prioritized in-process .NET Cryptography (`CertificateRequest` and `X509Certificate2` with `Exportable` + encrypted PKCS#8 re-import for Windows CNG compatibility) in `SSLCertificateService`, and parameterized fallback PowerShell/OpenSSL execution using `ProcessStartInfo.ArgumentList`, scoped environment variables, and `StandardInput` (`-passin stdin`).
- Enforced synchronous Apache configuration validation (`httpd.exe -t`) before reporting virtual host creation success.
- Added transactional rollback in `PackageInstaller.InstallPackageAsync` so newly created installation directories and temporary archives are cleaned up on failure.
- Removed unused vulnerable NuGet packages from `ModStack.GUI.csproj` to achieve a zero-vulnerability (`NU1903`-free) build.

## Problems and Solutions

- **Problem**: `X509Certificate2(pfxPath, password, X509KeyStorageFlags.Exportable)` on Windows CNG enables encrypted key export (`AllowExport`) but not plaintext key export (`AllowPlaintextExport`), causing `privateKey.ExportRSAPrivateKey()` to throw `CryptographicException: The requested operation is not supported`.
- **Solution**: Exported the private key as encrypted PKCS#8 (`ExportEncryptedPkcs8PrivateKey` with AES-256-CBC / SHA-256) and imported it into an ephemeral `RSA.Create()` instance before calling `ExportRSAPrivateKey()`.
- **Problem**: `ConfigurationTypeHandler.ConvertJsonElementToObject` used `element.TryGetInt32(out var intVal) ? intVal : element.GetDouble()`, which implicitly widened `intVal` to `double` in C# ternary type inference.
- **Solution**: Extracted `ConvertNumberElement(JsonElement)` with explicit `if / return` branches so 32-bit integers remain `int` even when IDE code formatters run.
- **Problem**: Running as standard user (`asInvoker`) caused `process.MainModule?.FileName` to throw `Win32Exception (Access is denied)` for elevated `httpd.exe` instances, falsely reporting Apache as "Stopped" and causing a subsequent Start click to fail with `OS 10048` (port 80 already bound) and `AH00015: Unable to open logs`. Furthermore, `CheckExternalPortUsageAsync` passed `| findstr` directly to `netstat.exe` with `UseShellExecute = false`.
- **Solution**: Restored `requireAdministrator` in `app.manifest` and `PrivilegesRequired=admin` in `ModStack.iss` (while keeping the custom startup popup removed), added a Win32 `QueryFullProcessImageName` fallback in `ServiceControlManager.TryGetProcessExecutablePath`, and parsed `netstat -ano` output directly in C#.
